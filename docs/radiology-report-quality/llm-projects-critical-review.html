02 / 08 Shared foundation & divergences

One domain, two setups - not yet aligned

Common ground
  • Domain: French trauma X-ray reports, section-structured (Indication / Description / Conclusion)
  • Yardstick: BoneView intended use - fracture, dislocation, effusion, bone lesion; limbs, pelvis, thoraco-lumbar spine, rib cage; ≥2 y
  • Privacy: on-prem / local inference, no cloud egress - RGPD-aligned
  • Approach: an LLM applies an explicit, versioned rule set to free text
Divergences to reconcile
  • Different models: Claude Opus 4.8 (P1) vs Mistral 7B (P2) - not comparable, very different capability
  • Different "ambiguity"/"doubt" definitions across the two pipelines
  • Follow-up is a standalone metric in P1's world but is gated on ambiguity in P2
  • No human-validation (κ) executed yet for either project's LLM labels

Both projects are promising and mutually reinforcing - but they must share a model tier, a scope definition, and a validation protocol to be comparable.

03 / 08 Project 1 · Summary

AI vs report concordance - context sets the value of a doubt alert

Design
  • Cohort: 888 BoneView DOUBT alerts, randomly sampled from 2025, 20-site network (Romandie), mature deployment
  • Method: LLM (Claude Opus 4.8) applies an arbitrated rule set - Intended-use fit from Indications; ground truth (Anomaly / Doubt / Negative) from Conclusion
  • Primary metric: confirmation rate = Anomaly / (Anomaly + Negative)
  • Reference: the radiologist report (no image re-read)

04 / 08 Project 1 · Critical review

Strong thesis, but the reference standard limits the claim

Holds up
  • Clinically important, novel angle: context determines alert value
  • Large, real-world, mature deployment; monotone dose-response gradient
  • Anatomy-adjusted logistic regression; Wilson CIs; sensible sensitivity analyses
  • COI (Gleamer equity) disclosed and mitigated by independent extraction
Needs fixing
  • Incorporation bias: report = reference, yet AI output was available before/during reporting in 93% - reference not independent of the index test
  • Doubt-only cohort: no sensitivity/specificity possible; only confirmation-among-resolved
  • GT from free text, unvalidated: no LLM-vs-radiologist κ yet; case-level only, no localisation
  • Effusion scope conflict: effusion-without-fracture coded Negative, but it is within BoneView intended use - systematic GT misalignment
⚠ Data-integrity flag - numbers diverge across source documents

MICCAI camera-ready: N=888, in-scope 300, confirmation 50.6%. IAD analysis sheet: N=888, Fit 305, confirmed-among-resolved 48.2%. RSNA Abstract v1: N=925, eligible 322, confirmation 47.0%. Three cuts, three numbers - lock one frozen dataset before any submission.

06 / 08 Project 2 · Critical review

Right metrics, but under-powered model and no validation

Holds up
  • Fully local, deterministic setup (temp 0) - strong privacy posture
  • Clinically meaningful metric set; laterality & structure are high-value safety checks
  • Structural gate before semantic checks is sound engineering
Needs fixing
  • No ground truth: no precision/recall vs the 50-report single-radiologist gold; accuracy unknown
  • Mistral 7B is too small for cross-section laterality reasoning & nuanced ambiguity - error-prone, and inconsistent with P1's Opus-class model
  • Follow-up gated on ambiguity misses missing-follow-up on definite actionable findings; decouple presence (Q2) from completeness (Q3)
  • Ambiguity by vague-word spotting over-flags clear negatives with cautious wording - needs rubric-anchored "hedge resolved by action = not ambiguous"
  • Over-flag risk: "missing laterality for paired organs" & spelling-vs-jargon are false-positive magnets at 7B

The earlier 50-report single-radiologist ambiguity + follow-up annotations are exactly the gold set needed to measure this pipeline - currently unused for validation.

07 / 08 Cross-cutting concerns

Three issues that affect both projects

1 · Trust

Labels are unvalidated

Both rely on LLM-derived labels from free text with no human-agreement study. A two-radiologist κ protocol is drafted but not run. Until then, every downstream number inherits unknown measurement error.

2 · Consistency

Definitions & models diverge

"Ambiguity/doubt", intended-use scope (esp. effusion), and the model tier differ between projects. Same construct must mean the same thing and be judged by the same-strength model to be comparable.

3 · Claims vs design

Metric ≠ study design

A doubt-enriched, report-referenced cohort supports concordance/appropriateness claims - not diagnostic accuracy. Accuracy needs device-output-balanced sampling + image-based adjudication.

Governance

Neither package yet fixes provenance for submission: institution, dates, IRB/waiver, BoneView software version, random seed, and rule-set version. Version the rule set; re-run only when rules change.

08 / 08 Required adjustments of methods

What to change before submission / deployment

  1. Lock one frozen dataset & reconcile the numbers. Resolve 888 vs 925 and 50.6 / 48.2 / 47.0%; single source of truth feeds every figure.P1 · now
  2. Run the two-radiologist validation (κ). Blinded, seeded, stratified subset; target κ ≥ 0.61 (min) / 0.81 (goal); report confusion matrix. Applies to both projects' LLM labels.Both · now
  3. Fix the reference-standard bias. State incorporation bias explicitly; for any accuracy claim move to a device-output-balanced cohort (add ~+80 AI-positive, ~+85 AI-negative) with image-based (Level-2) adjudication; report PPV/NPV per output, not sens/spec.P1
  4. Align ground truth with true BoneView intended use. Decide effusion / dislocation / bone-lesion handling once; stop coding in-scope effusion as Negative. One scope definition shared by both projects.Both
  5. Unify model & rubric. Use one judge-grade model (validate Mistral 7B against Opus-class or upgrade); one rubric-anchored ambiguity definition; decouple follow-up presence from ambiguity; share the intended-use lexicon.P2
  6. Power & report properly. Enrich thin arms to ~100–170/arm; validate P2 on the 50-report single-radiologist gold with per-metric precision/recall; fix provenance, seed, and rule-set version for reproducibility.Both
